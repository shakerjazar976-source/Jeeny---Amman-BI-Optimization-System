Appendix D: Code Structure and Reproducibility

The project code was structured to make the analysis repeatable. This means that when a new Jeeny dataset becomes available, the same scripts can be rerun to generate updated outputs under the same folder names and file names.

**Table 28. Code Structure.**

| Code Block | Purpose |
| --- | --- |
| Configuration | Defines input file, output folders, target city, and model settings |
| Helper Functions | Saves charts and tables, performs scaling, safe division, and text cleaning |
| Data Loading and Cleaning | Loads the dataset, checks required columns, converts data types, and applies cleaning rules |
| Feature Engineering | Creates Revenue_per_Minute, Fare_per_Km, Duration_per_Km, IsHighRisk, IsPeak, Hour, Month, Weekday, and Date |
| City Analysis | Generates city dominance and city summary outputs |
| Zone Analysis | Generates Amman pickup-zone performance outputs |
| Hourly Analysis | Measures demand, revenue, and risk by hour |
| OD Analysis | Analyzes movement between pickup and dropoff zones |
| Risk Intelligence | Segments risk by zone, hour, payment method, and OD pair |
| Payment and Customer Segmentation | Analyzes payment method and customer-related patterns |
| ABI Scoring | Calculates the Amman Bottleneck Index |
| Demand Prediction | Estimates hourly-zone demand using Random Forest or historical fallback |
| Driver Allocation | Recommends driver distribution by hour and pickup zone |
| What-if Scenarios | Simulates improvement scenarios |
| Chart Generation | Exports visual outputs as PNG files |
| Report Export | Exports CSV, Excel, and HTML deliverables |

Appendix F: Data Improvement Suggestions

The dataset can be improved by adding more operational variables. These improvements would make the BI system more accurate and useful for real decision-making.

**Table 30. Suggested Data Improvements.**

| Data Area | Current Issue | Suggested Improvement | BI Value |
| --- | --- | --- | --- |
| GPS Coordinates | Pickup and dropoff zones are categorical only | Add pickup_latitude, pickup_longitude, dropoff_latitude, dropoff_longitude | Enables real heatmaps and spatial bottleneck detection |
| Driver Information | No driver-level availability data | Add Driver_ID, Driver_Status, Acceptance_Rate, Cancellation_Rate, Online_Minutes | Supports accurate driver allocation |
| Customer Information | Limited customer segmentation | Add Customer_ID, Customer_Type, Loyalty_Level, Trip_Frequency | Improves customer behavior and retention analysis |
| Trip Lifecycle | Only trip time and duration are available | Add request_time, driver_accept_time, pickup_time, dropoff_time | Measures waiting time and pickup delay |
| Cancellation Data | Cancellation reasons are not deeply analyzed | Add Cancellation_Flag, Cancellation_Reason, Cancelled_By | Identifies lost demand and failed trips |
| Traffic Conditions | No congestion indicator | Add Traffic_Index or Congestion_Level by zone-hour | Explains long duration and route inefficiency |
| Weather | Weather impact is not captured | Add Weather_Status, Rain_Flag, Temperature | Improves demand forecasting |
| Fare Breakdown | Fare is available but not detailed | Add base_fare, distance_fare, time_fare, surge_multiplier, discount | Supports pricing and profitability analysis |
| Promotions | No coupon or campaign tracking | Add Promo_Code, Discount_Value, Campaign_Name | Measures marketing effectiveness |
| Service Quality | No rating or complaint fields | Add Customer_Rating, Driver_Rating, Complaint_Flag | Connects operations with satisfaction |
| Flight Data | Airport demand is not connected to flight arrivals | Add flight_arrival_count or flight_peak_indicator | Improves airport driver positioning |
| Real Cost Data | No operating cost per trip | Add driver_cost, fuel_proxy, commission, platform_margin | Allows real profitability analysis |
